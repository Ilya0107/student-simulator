# Архитектура / Architecture

## Обзор

`student-simulator` — консольная текстовая игра на C++17 для Windows. Код сознательно
разделён на **данные** и **логику**: весь контент (тексты, варианты выбора, эффекты,
концовки, ASCII-арт) вынесен в отдельную таблицу, а не разбросан по условиям.

```
+-------------------------------------------------------------------+
|                            main.cpp                               |
|  main() -> choosePlayer() -> цикл на 10 дней -> player::exam()    |
|            tryDream(), waitForEnter()                             |
+------------------------------+------------------------------------+
                               | использует
             +-----------------+------------------+
             |                                    |
     +-------v--------+                   +-------v---------+
     |  player.{h,cpp}|                   | text_data.{h,cpp}|
     |  класс Player  |<------- Effect ---|  DAYS[10]        |
     |  applyEffect() |                   |  DREAMS[6]       |
     |  printStats()  |                   |  END_* (строки)  |
     |  printGradebook|                   |  ART_* (ASCII)   |
     |  exam()        |                   +------------------+
     +-------+--------+
             |
     +-------v--------+
     |  color.{h,cpp} |
     |  setColor()    |  обёртка над SetConsoleTextAttribute (WinAPI)
     |  resetColor()  |
     +----------------+
```

## Модули

### `main.cpp` — сценарий и игровой цикл

- `choosePlayer()` — приветствие, выбор персонажа и стартового бонуса, создаёт `player`.
- `tryDream(player&, int& chance)` — случайное испытание между днями; меняет шанс сна
  (`+10` при отсутствии сна до `45`, `-15` при сне до `10`).
- `waitForEnter()` — пауза до нажатия Enter (заменяет `system("pause")`, убирая
  зависимость от командной оболочки и англоязычного текста).
- `main()` — настраивает кодировку консоли (`CP_UTF8`), инициализирует ГПСЧ,
  прогоняет 10 дней и вызывает `A.exam()`.

### `player.{h,cpp}` — модель игрока и финал

- Хранит `health`, `knowledge`, `money`, `name`.
- `applyEffect(Effect)` — единственная точка изменения характеристик.
- `printStats()` / `printGradebook(grade)` — форматированный вывод с цветом
  (пороговая логика цвета: красный / жёлтый / зелёный).
- `checkEnd()` — досрочное поражение (здоровье ≤ 0 или деньги < 0).
- `exam()` — финальная ветка: проверки на «смерть», уход в бизнес/спорт, расчёт
  оценки, опциональный подкуп и выбор концовки.

### `text_data.{h,cpp}` — контент как данные

- `Effect { health, knowledge, money }` — дельта характеристик.
- `Choice { text, effect }`, `DayData { title, location, description, choices[4] }`.
- `DAYS[10]` — 10 дней по 3 варианта.
- `DREAMS[6]`, `WELCOME_TEXT`, `ART_*`, `END_*` — тексты, сны, арт и концовки.

Такой формат позволяет добавлять контент без изменения логики: чтобы расширить игру,
достаточно дополнить таблицу `DAYS`/`DREAMS`.

### `color.{h,cpp}` — цвета консоли

- `enum ConsoleColor` — именованные цвета.
- `setColor(text, bg)` / `resetColor()` — тонкая обёртка над
  `SetConsoleTextAttribute`. Отдельный модуль убирает прямые вызовы WinAPI из игровой
  логики.

## Технические решения

| Решение | Обоснование |
|---|---|
| Контент отделён от логики (`text_data`) | Новый контент не требует правок игрового кода |
| Исходники в UTF-8, `/utf-8`, консоль `CP_UTF8` | Корректная кириллица и на GitHub, и в консоли |
| Обёртка `color.*` над WinAPI | Изоляция платформенного кода, читаемость |
| `waitForEnter()` вместо `system("pause")` | Без вызова shell, локализованный текст |
| CI на GitHub Actions | Автоматическая проверка сборки на каждом push |

## Известные ограничения и точки роста

- **Только Windows** — из‑за `windows.h` / консольного API. Кроссплатформенность
  потребовала бы абстракции вывода (например, ANSI-escape на POSIX).
- `using namespace std;` в заголовках — стоит убрать в пользу явных `std::`.
- Вывод эффектов в `main.cpp` дублируется для дня и для сна — просится единый
  helper или `operator<<` для `Effect`.
- Балансовые константы (стартовые характеристики, `-20` в день, шансы сна) заданы в
  коде; их можно вынести в конфиг.
- Нет автоматических тестов — логику `exam()` и расчёт оценки можно покрыть
  модульными тестами.
